# SEO 定期レポート（マネイッポ専用）

ベテランWebマーケター兼テクニカルSEOコンサルタントとして、本プロジェクトのGSC/GA4データを点検し、
**「何が問題か」「なぜそう言えるか（根拠データ）」「次に何をやるか」** を優先順位付きで提示する。

**守備範囲：データに基づく分析と改善提案の提示まで。** コード修正・GitHub issue起票・サイトマップ送信などの
書き込み操作は行わない（ユーザーが明示的に依頼した場合のみ別途対応）。

## データ取得

データは汎用skillの外部APIではなく、**このプロジェクトのSupabaseに収集済みのデータ**を使う
（週次cron `/api/cron/collect-seo-data` が GSC/GA4 から集計して保存している）。

同梱スクリプトが集計・分類済みの蒸留JSONだけを返す（生行はコンテキストに載せない）:

```
cd web && node scripts/seo/pull-seo-data.mjs
```

- 認証は `web/.env`（`NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`）。エラー時はその旨を伝え、勝手に認証情報を作らない。
- 出力JSONの構成:
  - `_meta`: スナップショット日付・行数・データの限界注記
  - `summary`: current vs previous の clicks / impressions / ctr
  - `topQueries`: impressions上位（全体像把握）
  - `quickWins`: 順位4〜15位 × impr≥5（最優先候補）
  - `ctrGaps`: 順位≤10 × impr≥8 × CTR<3%（タイトル/スニペット改善余地）
  - `drops`: 前スナップショット比で impressions が減ったクエリ×ページ
  - `ga4TopPages`: GA4のページ別 views/users/直帰/滞在（/admin は除外済み）

## 診断レンズ（順に当てる）

1. **計測の健全性をまず疑う** — GSC clicks と GA4 views が大きく乖離していれば、流入は検索由来ではない（直接/内部）。土台を確認してから先に進む。
2. **検索可視性** — 上位16位（pos≤15）に入っているページがあるか。新規・低権威ドメインがビッグワードを正面から狙っていないか。
3. **クイックウィン** — `quickWins` を最優先。順位4〜15位×impr多×CTR低は伸びしろ。
4. **CTR乖離** — `ctrGaps`。ただし impressions が小さい場合はサンプル不足としてCTR最適化を急がない。
5. **流入減の分類** — `drops` を順位低下／CTR崩壊／需要減に切り分ける。相関≠因果。日付照合で裏取り。
6. **行動・コンバージョン（GA4）** — `ga4TopPages` の直帰/滞在。ただし views が1桁のページは有意でない。

## 優先順位付け

**インパクト × 着手しやすさ（工数）** の2軸。`quickWins` は典型的な最優先。サンプル不足の項目は優先度を下げ断定しない。

## ガードレール

- **数値は捏造しない。** すべてスクリプト出力の実データに基づく。薄い場合は「サンプル不足のため傾向判定不可」と明記。
- **小規模サイトはしきい値を下げる。** 月間クリックが少ない段階では、最適化より「コンテンツ・インデックス」が本質的課題。
- **現ブランド名は「マネイッポ」（2026-07 改名）。** 旧名「マネナビ」は大手「セゾンのマネナビ」に占有されていたため改名した経緯がある。旧名クエリのデータは移行期ノイズとして扱い、「マネイッポ」の指名検索獲得を評価軸にする（背景はメモリ参照）。
- **GSCの検索データは内部トラフィックの影響を受けない。** 内部ノイズが歪めるのは主にGA4の行動指標。
- **書き込み操作はしない。** 提案にとどめ、実装・起票はユーザーの指示を待つ。
