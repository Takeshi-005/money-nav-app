## 設計の目的

### なぜゲーミフィケーション？

```
┌─────────────────────────────────────────┐
│  投資学習の最大の敵は「続かないこと」    │
└─────────────────────────────────────────┘
```

| 課題 | ゲーミフィケーションの解決策 |
|------|---------------------------|
| 学習が続かない | 経験値・レベルで達成感を提供 |
| 成長が見えない | 進捗を数値で可視化 |
| モチベーション低下 | ボーナスで継続を促進 |

## 経験値（EXP）システム

### 経験値の配分

| 行為 | 獲得EXP | 設計意図 |
|-----|--------|---------|
| クイズ正解 | +10 | 正解への報酬（達成感） |
| クイズ参加 | +2 | 参加障壁を下げる（習慣化） |
| 全問正解ボーナス | +15 | 完璧への報酬 |
| 診断完了 | +15 | 初回診断完了で習慣化のトリガーを提供 |

### 📚 学習ポイント: なぜ不正解でも+2？

```
【心理学的根拠】

❌ 不正解 = 0 EXP の場合
- 「間違えたら損」という感覚
- 挑戦を避けるようになる
- 学習から離脱

✅ 不正解 = +2 EXP の場合
- 「参加すれば必ず成長」という感覚
- 気軽に挑戦できる
- 学習を継続
```

**BJ Fogg のモデル**: 行動 = 動機 × 能力 × トリガー
- 参加報酬は「動機」を維持する役割

## レベルシステム

### レベルアップ基準

| レベル | 必要EXP | 累計EXP | 到達目安 |
|--------|---------|---------|---------|
| Lv.1 → 2 | 50 | 50 | 約1週間 |
| Lv.2 → 3 | 100 | 150 | 約2週間 |
| Lv.3 → 4 | 150 | 300 | 約3週間 |
| Lv.4 → 5 | 200 | 500 | 約1ヶ月 |
| Lv.5 以降 | 200/Lv | - | 継続的 |

### 📚 学習ポイント: なぜ段階的に難しくなる？

```
【ゲームデザインの原則】

序盤:  簡単にレベルアップ → 達成感を早期に提供
中盤:  徐々に難しく → 挑戦意欲を維持
終盤:  一定の難度 → 長期継続を促進

┌─────────────────────────────────────┐
│ EXP                                │
│ 500 ─────────────────────●Lv5     │
│ 300 ─────────────●Lv4             │
│ 150 ─────●Lv3                     │
│  50 ●Lv2                          │
│   0 ●Lv1                          │
└─────────────────────────────────────┘
```

### 実装例

```typescript
// src/lib/gamification.ts

export function calculateLevel(experience: number): number {
  // Lv1-4: 段階的に必要経験値が増加
  if (experience < 50) return 1
  if (experience < 150) return 2
  if (experience < 300) return 3
  if (experience < 500) return 4

  // Lv5以降: 200 EXP ごとにレベルアップ
  return 5 + Math.floor((experience - 500) / 200)
}

export function getExpForNextLevel(currentLevel: number): number {
  const thresholds = [0, 50, 150, 300, 500]

  if (currentLevel < 5) {
    return thresholds[currentLevel]
  }

  // Lv5以降
  return 500 + (currentLevel - 4) * 200
}
```

### 📚 学習ポイント: 計算式の設計

```typescript
// なぜこの計算式？

// 方法1: 配列で管理（シンプルだが拡張性低い）
const levels = [0, 50, 150, 300, 500, 700, 900, ...]

// 方法2: 数式で計算（拡張性高い）← 採用
return 5 + Math.floor((experience - 500) / 200)

// メリット:
// - レベル上限がない
// - メモリ効率が良い
// - 計算が高速
```

## ボーナスシステム

### 全問正解ボーナス

```
通常:   3問 × 10 EXP = 30 EXP
ボーナス: +15 EXP
合計:   45 EXP

→ 全問正解で 1.5倍の報酬
```

### 📚 学習ポイント: なぜ全問正解ボーナス？

| 設計 | 効果 |
|------|------|
| ボーナスなし | 1問だけ正解でも満足してしまう |
| ボーナスあり | 全問正解を目指す動機が生まれる |

## 効果測定（KPI）

### 追跡すべき指標

| 指標 | 目標 | 意味 |
|------|------|------|
| DAU（日次アクティブユーザー） | - | 毎日使っている人数 |
| 継続率（7日） | 50%+ | 1週間後も使っている割合 |
| 継続率（30日） | 30%+ | 1ヶ月後も使っている割合 |
| 平均セッション時間 | 3分+ | 1回の利用時間 |

### 📚 学習ポイント: 成功の定義

```
ゲーミフィケーションの成功 = 継続率の向上

継続率が上がらない場合:
- 報酬が魅力的でない
- 難易度が適切でない
- フィードバックが不足

→ 数値を見て改善を繰り返す
```
